## 概述

一個在瀏覽器裡比較兩種骨折治療方案的 3D 互動檢視器：同一個股骨幹骨折，左右並排兩種固定或負重方案，拖動時間軸看骨痂逐週生成，並用圖表比較關鍵指標。目標是 5 天內做出可公開展示的 MVP。

**要解決的問題**

骨折癒合模擬會產生大量隨時間變化的力學與組織資料。臨床醫師需要的不是一張靜態快照，而是能並排比較方案、看懂差異的介面。這個專案展示如何把這類模擬結果做成專家用得懂的產品介面。

**目標**

- 在 3D 模型上呈現隨時間變化的數值（骨痂組織狀態）
- 兩個方案同步比較：同一個骨折，兩個視角鏡頭連動
- 3D 與圖表雙向連動：時間軸、圖表游標、3D 狀態一致
- 部署成公開網址，桌機流暢運作（60 fps）

**非目標**

- 不做真實的有限元素或生物力學模擬，數據為示意模型
- 不讀取 DICOM 或真實病人資料
- 不做登入、後端、資料儲存
- 不提供任何醫療建議

## 目標使用者與使用情境

主要讀者是醫療模擬新創的工程主管與創辦人，他們會在 1 到 2 分鐘內判斷作者能不能把模擬結果做成好用的介面。介面本身則假設使用者是骨科醫師或課程學員。

**使用者故事**

1. 身為醫師，我想看到同一個骨折在兩種方案下的 3D 剖面，才能直觀比較固定方式的差異。
2. 身為醫師，我想拖動時間軸看骨痂從第 0 週長到第 20 週，才能理解癒合是一個過程。
3. 身為醫師，我想切換釘子直徑或負重等級，立刻看到兩方案的指標變化。
4. 身為醫師，我想點圖表上的某一週，3D 模型就跳到那一週的狀態。
5. 身為課程講師，我想按播放讓整個癒合過程自動跑一遍，方便課堂說明。

**MVP**

| # | 功能 | 說明 |
| --- | --- | --- |
| F1 | 案例資訊面板 | 固定一個示範案例：股骨幹骨折、骨折間隙 3 mm、髓內釘固定 |

**延伸功能**

- 癒合里程碑標記（例如骨橋形成的那一週）
- 兩方案差異圖
- 截圖匯出
- 手機版排版

## 技術架構

純前端單頁應用，所有資料預先算好放在 JSON，沒有後端。

| 層級 | 選擇 |
| --- | --- |
| 建置 | Vite + React + TypeScript |
| 3D | React Three Fiber + drei（`View`、`OrbitControls`、`useGLTF`） |
| 狀態 | Zustand：目前週數、播放狀態、A/B 方案參數、共用相機 |
| 圖表 | Recharts 或 visx（見待決問題） |
| 樣式 | CSS Modules 或 Tailwind |
| 部署 | Vercel 或 GitHub Pages |

**資料流**

1. 啟動時載入股骨 glb 與 `scenarios.json`
2. 使用者改變週數或方案 → 更新 Zustand store
3. 3D 元件訂閱 store，把對應週數的數值傳進骨痂 shader 的 uniform
4. 圖表訂閱同一個 store，移動游標；點擊圖表反向寫回週數

**目錄結構**

```
src/
  scene/        FemurModel, Nail, Callus, ComparisonViews
  shaders/      callus.vert, callus.frag
  charts/       MetricChart
  ui/           CasePanel, Timeline, ScenarioControls, Legend, Disclaimer
  store/        useViewerStore.ts
  data/         scenarios.json, generateScenarios.ts
public/models/  femur.glb
```

## 3D 素材與渲染

股骨用 BodyParts3D 的右股骨（FMA24474），在 Blender 處理後匯出成單一 glb；髓內釘和骨痂都用程式產生。

**Blender 處理流程**

1. 匯入 `FMA24474.obj`，Subdivision + Smooth 修正 99% 減面造成的粗糙
2. 在股骨幹中段用平面切開，兩段之間留 3 mm 骨折間隙
3. 用 Boolean 挖出髓腔，讓剖面看得到內部
4. 統一座標與比例（單位 mm，骨幹長軸對齊 Y 軸）
5. 匯出 glb，目標檔案小於 2 MB（必要時用 Draco 壓縮）

**渲染做法**

- **剖面**：用 clipping plane 沿長軸切開，並用 stencil 為切面補上實心蓋子，避免只看到空心殼的薄邊
- **髓內釘**：`CylinderGeometry`，直徑跟方案參數連動，加上上下各兩個鎖定螺絲
- **骨痂**：包在骨折間隙周圍的旋轉體（`LatheGeometry`），由自訂 shader 依 `uWeek` 控制生長範圍與顏色；每個頂點依距離骨折線的遠近決定組織狀態
- **雙視角**：一個 `Canvas` + drei `View` 畫兩個區塊，共用同一份模型資源；兩個視角共用一組相機參數達成同步
- **效能**：只在週數或方案改變時更新 uniform，不重建幾何

## 示意資料模型

4 種方案組合（2 種釘子直徑 × 2 種負重）各算 21 週（第 0 到 20 週）的數值，由 `generateScenarios.ts` 在建置時產生 `scenarios.json`。公式只求趨勢合理，數值皆為示意。

**參數係數**

| 參數 | 選項 | 係數 |
| --- | --- | --- |
| 釘子直徑 | 10 mm / 11 mm | 剛性係數 k\_nail = 1.0 / 1.25 |
| 負重 | 部分 / 完全 | 負重係數 k\_load = 1.0 / 1.6 |

**公式**

碎片間移動（mm）：

```latex
IFM(t) = 0.8 \cdot \frac{k_{load}}{k_{nail}} \cdot e^{-t/\tau}
```

癒合程度（%）：

```latex
C(t) = 100 \cdot \left(1 - e^{-t/\tau_c}\right)
```

植入物應力（MPa）：

```latex
\sigma(t) = 220 \cdot \frac{k_{load}}{k_{nail}} \cdot \left(1 - 0.7 \cdot \frac{C(t)}{100}\right)
```

當初始 IFM 大於 1.1 mm（移動過大）時，癒合變慢：τ = 6、τc = 8；否則 τ = 4、τc = 5（單位：週）。這樣「完全負重 + 細釘」會呈現延遲癒合，形成有意義的對比。

四種組合的初始 IFM（驗算門檻）：

| 方案 | k\_load / k\_nail | 初始 IFM | 癒合速度 |
| --- | --- | --- | --- |
| 10 mm + 部分 | 1.00 | 0.80 mm | 正常 |
| 11 mm + 部分 | 0.80 | 0.64 mm | 正常 |
| 10 mm + 完全 | 1.60 | 1.28 mm | 延遲 |
| 11 mm + 完全 | 1.28 | 1.024 mm | 正常 |

**JSON 結構**

```
{
  "case": { "bone": "femur", "fractureGapMm": 3, "fixation": "intramedullary nail" },
  "scenarios": [
    {
      "id": "nail10-partial",
      "nailDiameterMm": 10,
      "loading": "partial",
      "weeks": [
        { "week": 0, "ifmMm": 0.8, "implantStressMpa": 220, "consolidationPct": 0 }
      ]
    }
  ]
}
```

骨痂組織狀態不存進 JSON，由 shader 依 `C(t)` 與頂點到骨折線的距離即時計算。

## 介面配置

桌機版（1280 px 以上）為單一畫面，不需捲動即可看到 3D、時間軸與圖表。

```
+----------------------------------------------------------+
| 標題列                                 免責聲明標籤       |
+-----------+----------------------------------------------+
| 案例資訊   |   方案 A 3D 剖面   |   方案 B 3D 剖面        |
|           |   [直徑][負重]     |   [直徑][負重]          |
| 色階圖例   |                    |                         |
+-----------+----------------------------------------------+
|  ▶  ────────●──────────────────  第 8 週 / 20           |
+----------------------------------------------------------+
|  碎片間移動    |   植入物應力    |   癒合程度             |
+----------------------------------------------------------+
```

- 視覺風格：淺色臨床介面，中性灰底；方案 A、B 各用一個固定顏色，在 3D 標籤與圖表線條中保持一致
- 組織色階與方案顏色分開，避免混淆
- 鍵盤：空白鍵播放／暫停，左右鍵前後一週

## 關鍵決策、授權與待決問題

**關鍵技術決策**（README 要寫，面試也可能被問）

| 決策 | 選擇 | 理由 |
| --- | --- | --- |
| React Three Fiber vs 純 Three.js | R3F | 3D 與 UI 共用 React 狀態，連動邏輯簡單；必要時仍可直接操作 Three.js 物件 |
| 一個 Canvas + View vs 兩個 Canvas | 一個 Canvas | 避免兩個 WebGL context，模型與材質只載入一次 |
| 預先計算 vs 前端即時計算 | 預先計算 | 真實模擬在後端跑，前端只負責呈現，跟實際產品架構一致 |
| 剖面：clipping vs 半透明 | clipping + stencil 蓋子 | 半透明會有排序問題且看不清內部；剖面是醫師熟悉的視角 |
